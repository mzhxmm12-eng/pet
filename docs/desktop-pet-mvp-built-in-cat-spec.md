# 桌面宠物 MVP 与资产规范

## 1. 文档目标

本文档定义 Windows 桌宠客户端第一阶段的产品范围、行为规范、文件投喂交互和宠物资产协议。

本阶段先不接入网页端素材生成，也不导入用户照片生成的宠物。优先制作一只内置像素猫，验证桌宠在 Windows 桌面的常驻展示、状态切换、光标互动、拖拽投喂和资产播放规范。

后续网页端生成器、自定义宠物导入、第三方宠物包都必须遵守本文档定义的 `.deskpet` 资产结构和动作语义，避免客户端逻辑被素材来源绑死。

## 2. 产品定位

### 2.1 第一阶段目标

让用户打开客户端后，桌面上出现一只可爱的像素猫。它会自己待机、走动、睡觉，会被光标吸引，也能把用户拖过来的废弃文件当作猫粮吃掉，并在投喂完成后把文件移入系统回收站。

### 2.2 核心体验循环

```text
启动应用
  -> 内置猫出现在桌面
  -> 猫在桌面待机/走动/睡觉
  -> 用户用光标靠近或逗弄
  -> 猫警觉、看向光标、扑一下
  -> 用户拖拽废弃文件到猫身上
  -> 猫进入吃东西动画
  -> 文件进入系统回收站
  -> 猫恢复日常状态
```

### 2.3 MVP 不做

1. 不做网页端生成素材导入。
2. 不做用户照片生成宠物。
3. 不做复杂养成、等级、亲密度系统。
4. 不做多宠物同时运行。
5. 不做聊天 AI、摸鱼工具箱、键鼠统计。
6. 不做商城、社区和账号体系。

## 3. 目标用户与使用场景

### 3.1 目标用户

主要面向 Windows 办公、学习、写代码用户。他们希望桌面上有一个轻量、可爱、不打扰的陪伴物，也希望删除废弃文件这类日常小动作变得更有趣。

### 3.2 使用原则

1. 可爱但不烦：默认低频动作，不主动遮挡用户工作。
2. 本地优先：客户端行为、素材、设置都在本地完成。
3. 明确可控：用户可以隐藏、暂停、退出、重置位置。
4. 删除谨慎：投喂文件本质是移动到回收站，必须有明确反馈和可撤销路径。

## 4. 客户端产品面

### 4.1 桌宠窗口

桌宠以透明无边框窗口显示，窗口只包裹宠物可见区域。

必须支持：

1. 透明背景。
2. 始终置顶或桌面层显示。
3. 鼠标拖拽移动宠物。
4. 右键菜单。
5. 多显示器边界识别。
6. DPI 缩放适配。
7. 一键找回到主屏幕中央。

### 4.2 托盘菜单

托盘菜单至少包含：

1. 显示/隐藏宠物。
2. 暂停/继续活动。
3. 点击穿透开关。
4. 允许文件投喂开关。
5. 重置位置。
6. 打开设置。
7. 退出。

### 4.3 设置页

MVP 设置项：

1. 宠物大小：`1x`、`1.5x`、`2x`、`3x`。
2. 动画速度：慢、标准、快。
3. 活跃程度：安静、标准、活跃。
4. 开机启动：开/关。
5. 点击穿透：开/关。
6. 文件投喂：开/关。
7. 投喂前确认：开/关，默认开。
8. 全屏应用时行为：保持、暂停、隐藏。

## 5. 宠物行为状态机

### 5.1 状态列表

MVP 状态必须包含：

| 状态 | 动作名 | 说明 |
| --- | --- | --- |
| 待机 | `idle` | 站立、眨眼、尾巴轻微摆动 |
| 行走左 | `walk_left` | 向左移动 |
| 行走右 | `walk_right` | 向右移动 |
| 睡觉 | `sleep` | 趴下或蜷缩，呼吸起伏 |
| 警觉 | `alert` | 光标靠近时抬头或看向光标 |
| 玩耍 | `play` | 光标快速经过、点击或逗猫时扑一下 |
| 被拖拽 | `dragged` | 用户拖动宠物本体 |
| 接收投喂 | `feed_ready` | 文件拖到宠物上方且可投喂 |
| 吃东西 | `eat` | 文件投喂成功后的吃东西动画 |
| 拒绝 | `reject` | 文件不可投喂或操作失败 |

`dragged`、`feed_ready`、`eat`、`reject` 在资产协议中可以先作为可选动作。若内置猫暂时没有独立素材，客户端可复用 `idle`、`alert`、`play` 做降级展示。

### 5.2 状态优先级

当多个状态同时满足时，按以下优先级处理：

```text
退出/隐藏
  > 用户拖拽宠物
  > 文件投喂悬停
  > 吃东西/拒绝反馈
  > 光标玩耍
  > 光标警觉
  > 睡觉
  > 行走
  > 待机
```

### 5.3 自动行为规则

1. 待机持续 8-20 秒后，随机选择继续待机、短距离走动或睡觉。
2. 行走距离建议为 80-240 px，不能走出当前屏幕工作区。
3. 睡觉持续 20-90 秒；光标靠近、点击、拖拽文件、右键菜单会唤醒。
4. 宠物碰到屏幕边界时，停止或转向。
5. 全屏应用场景下按用户设置暂停或隐藏。

### 5.4 光标逗猫规则

触发条件：

1. 光标进入宠物中心半径 160 px 内：进入 `alert`。
2. 光标在宠物附近快速移动：进入 `play`。
3. 用户左键点击宠物：进入 `play` 或短反馈动作。
4. 光标离开 3 秒后：恢复自动状态。

速度判断建议：

```text
cursorSpeed = distance(currentCursor, previousCursor) / elapsedMs
```

当光标在 250 px 范围内且速度超过阈值时，触发扑一下。为避免打扰，`play` 冷却时间建议不低于 2 秒。

### 5.5 拖拽宠物规则

1. 鼠标按住宠物可拖动位置。
2. 拖动过程中播放 `dragged`，无该动作则暂停当前帧。
3. 松开后保存当前位置。
4. 松开位置超出屏幕工作区时，自动吸附回最近可见区域。

## 6. 废弃文件投喂与回收站规范

### 6.1 功能目标

用户可以把不需要的文件拖到桌宠身上。宠物把文件当作猫粮吃掉，随后客户端将文件移动到 Windows 回收站。

该功能的真实语义是“趣味删除到回收站”，不是永久删除。

### 6.2 支持对象

MVP 支持：

1. 单个文件。
2. 多个文件。
3. 单个文件夹。
4. 多个文件和文件夹混合拖拽。

暂不支持：

1. 网络路径。
2. 回收站内文件。
3. 系统关键目录。
4. 正在被占用且无法移动的文件。
5. 需要管理员权限才能处理的文件。

### 6.3 交互流程

```text
用户拖拽文件进入宠物窗口
  -> 客户端读取拖拽对象路径
  -> 校验是否允许投喂
  -> 宠物进入 feed_ready
  -> 用户松手
  -> 若开启确认，弹出轻量确认
  -> 调用系统回收站移动能力
  -> 成功后播放 eat
  -> 失败后播放 reject 并提示原因
```

### 6.4 确认文案

默认必须开启投喂确认。确认弹窗文案：

```text
把这些文件喂给猫猫，并移入回收站？
```

按钮：

1. 确认投喂。
2. 取消。

当用户关闭“投喂前确认”时，设置页需要明确说明：拖到宠物身上的文件会直接移入回收站，可从系统回收站恢复。

### 6.5 回收站处理要求

1. 必须调用系统回收站能力，不能直接永久删除。
2. 移动失败时不得删除原文件。
3. 每个文件的处理结果要分别记录。
4. 多文件投喂时允许部分成功，但必须提示失败项数量。
5. 需要保留最近一次投喂结果，便于用户知道发生了什么。

Windows 实现建议：

1. .NET 可使用 `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile/DeleteDirectory` 并启用 `RecycleOption.SendToRecycleBin`。
2. 或使用 Win32 `IFileOperation` / `SHFileOperation`，并指定移动到回收站语义。
3. 后续若需要“撤销投喂”，优先引导用户打开系统回收站恢复；客户端不自建删除缓存。

### 6.6 安全边界

投喂前必须拒绝：

1. Windows 系统目录，如 `C:\Windows`。
2. 程序安装目录，如 `Program Files`。
3. 当前应用运行目录。
4. 用户配置目录中正在使用的宠物资产。
5. 空路径、非法路径、不可访问路径。

对于大文件夹或大量文件，建议提示数量和总大小，避免用户误操作。

## 7. 内置像素猫资产规范

### 7.1 美术方向

第一只内置宠物建议为“橘白像素猫”：

1. 类型：猫。
2. 风格：2D 可爱像素风。
3. 画布：64x64。
4. 背景：透明。
5. 默认朝向：向右。
6. 轮廓清晰，动作幅度小，适合常驻桌面。

### 7.2 必备动作

| 动作 | 帧数 | FPS | 说明 |
| --- | --- | --- | --- |
| `idle` | 4 | 4 | 眨眼、轻微呼吸 |
| `walk_right` | 6 | 8 | 向右走 |
| `walk_left` | 6 | 8 | 向左走，可由右走镜像 |
| `sleep` | 4 | 3 | 趴下睡觉 |
| `alert` | 3 | 5 | 抬头看光标 |
| `play` | 6 | 10 | 扑光标 |
| `eat` | 6 | 8 | 吃猫粮 |
| `reject` | 3 | 5 | 摇头或疑惑 |

### 7.3 推荐目录

开发期内置资产目录：

```text
assets/pets/orange-cat/
  manifest.json
  preview.png
  sprites/
    idle.png
    walk_right.png
    walk_left.png
    sleep.png
    alert.png
    play.png
    eat.png
    reject.png
```

发布后可以将该目录打包为内置资源，也可以复制到用户数据目录作为默认宠物。

## 8. `.deskpet` 资产包规范

### 8.1 文件本质

`.deskpet` 本质是 zip 文件，扩展名固定为 `.deskpet`。

客户端导入时只依赖 `manifest.json` 和 `sprites/`，不关心素材来自内置手绘、网页生成、用户导入或第三方制作。

### 8.2 标准结构

```text
pet-name.deskpet
  manifest.json
  preview.png
  sprites/
    idle.png
    walk_right.png
    walk_left.png
    sleep.png
    alert.png
    play.png
    eat.png
    reject.png
  previews/
    idle.gif
    walk_right.gif
    sleep.gif
    alert.gif
    play.gif
    eat.gif
```

`previews/` 为可选目录，仅用于客户端宠物管理页或网页端预览。

### 8.3 `manifest.json`

```json
{
  "formatVersion": 1,
  "petId": "orange_cat_builtin",
  "name": "Orange",
  "species": "cat",
  "style": "pixel_cute",
  "author": "DeskPet",
  "canvas": {
    "width": 64,
    "height": 64,
    "scale": 2
  },
  "hitArea": {
    "x": 10,
    "y": 8,
    "width": 44,
    "height": 52
  },
  "anchor": {
    "x": 32,
    "y": 60
  },
  "animations": {
    "idle": {
      "file": "sprites/idle.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 4,
      "fps": 4,
      "loop": true
    },
    "walk_right": {
      "file": "sprites/walk_right.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 6,
      "fps": 8,
      "loop": true
    },
    "walk_left": {
      "file": "sprites/walk_left.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 6,
      "fps": 8,
      "loop": true
    },
    "sleep": {
      "file": "sprites/sleep.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 4,
      "fps": 3,
      "loop": true
    },
    "alert": {
      "file": "sprites/alert.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 3,
      "fps": 5,
      "loop": false
    },
    "play": {
      "file": "sprites/play.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 6,
      "fps": 10,
      "loop": false
    },
    "eat": {
      "file": "sprites/eat.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 6,
      "fps": 8,
      "loop": false
    },
    "reject": {
      "file": "sprites/reject.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 3,
      "fps": 5,
      "loop": false
    }
  }
}
```

### 8.4 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `formatVersion` | 是 | 资产协议版本，MVP 固定为 `1` |
| `petId` | 是 | 宠物唯一标识，导入后可重新生成本地 ID |
| `name` | 是 | 宠物显示名 |
| `species` | 是 | 宠物类型，如 `cat`、`dog` |
| `style` | 是 | 美术风格，如 `pixel_cute` |
| `author` | 否 | 作者或来源 |
| `canvas` | 是 | 单帧逻辑画布和默认缩放 |
| `hitArea` | 否 | 鼠标命中区域，无则使用整张画布非透明区域 |
| `anchor` | 否 | 落地点锚点，用于贴边和移动计算 |
| `animations` | 是 | 动作定义 |

动画字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | Sprite Sheet 路径 |
| `frameWidth` | 是 | 单帧宽度 |
| `frameHeight` | 是 | 单帧高度 |
| `frames` | 是 | 帧数 |
| `fps` | 是 | 播放帧率 |
| `loop` | 是 | 是否循环 |

### 8.5 必须动作与可选动作

必须动作：

1. `idle`
2. `walk_right`
3. `walk_left`
4. `sleep`
5. `alert`
6. `play`

推荐动作：

1. `eat`
2. `reject`
3. `dragged`
4. `feed_ready`

客户端导入时，必须动作缺失则导入失败。推荐动作缺失时，客户端按降级规则复用已有动作。

### 8.6 Sprite Sheet 要求

1. PNG 格式。
2. 透明背景。
3. 横向排列。
4. 总宽度必须等于 `frameWidth * frames`。
5. 总高度必须等于 `frameHeight`。
6. 每帧宠物位置尽量稳定，不能明显漂移。
7. 单个资产包内所有动作建议使用同一画布尺寸。

## 9. 客户端分层建议

推荐按职责拆分，避免后续导入、生成和行为逻辑互相缠绕。

```text
DeskPet.App
  应用启动、托盘、设置窗口

DeskPet.Presentation
  透明宠物窗口、动画渲染、菜单 UI

DeskPet.Domain
  宠物状态机、行为规则、动作定义、投喂规则

DeskPet.Assets
  .deskpet 解包、manifest 校验、Sprite Sheet 解析

DeskPet.Platform.Windows
  Win32 窗口能力、全局鼠标、多显示器、回收站、开机启动

DeskPet.Storage
  本地设置、宠物索引、位置和投喂记录
```

核心原则：

1. 状态机不直接读写文件。
2. 渲染层不直接处理回收站。
3. 资产解析不关心宠物行为策略。
4. Windows 平台能力集中封装，便于测试和替换。

## 10. 验收标准

### 10.1 桌宠基础行为

1. 启动后内置猫能显示在桌面，背景透明。
2. idle、walk、sleep 能正常切换。
3. 宠物不会走出屏幕工作区。
4. 拖拽宠物后位置被保存。
5. 右键菜单可隐藏、暂停、退出。
6. 多显示器和 DPI 缩放下位置计算基本正确。

### 10.2 光标互动

1. 光标靠近时进入 alert。
2. 快速移动光标时触发 play。
3. 点击宠物有反馈。
4. 互动结束后能恢复自动状态。
5. 高频移动不会导致动画频繁抖动。

### 10.3 文件投喂

1. 拖拽文件到宠物身上能进入 feed_ready。
2. 松手后弹出确认。
3. 确认后文件进入系统回收站。
4. 取消后文件保持原位。
5. 失败时文件保持原位，并提示失败原因。
6. 多文件投喂有部分成功/失败反馈。
7. 系统目录和应用目录被拒绝投喂。

### 10.4 资产规范

1. 内置猫素材也使用 `manifest.json` 描述。
2. 客户端通过同一套解析逻辑加载内置宠物和外部 `.deskpet`。
3. 缺失必须动作时能给出清晰错误。
4. Sprite Sheet 尺寸与 manifest 不一致时导入失败。

## 11. 推荐开发顺序

1. 定义 `manifest.json` 数据结构和校验器。
2. 制作或占位内置橘白像素猫 Sprite Sheet。
3. 实现透明宠物窗口和 Sprite Sheet 播放。
4. 实现状态机：idle、walk、sleep。
5. 实现拖拽移动、位置保存和托盘菜单。
6. 实现光标感知：alert、play。
7. 实现文件拖拽投喂与移动到回收站。
8. 增加设置页：大小、速度、点击穿透、投喂确认。
9. 将内置猫按 `.deskpet` 协议打包，验证未来导入路径。

## 12. 后续扩展

### 12.1 自定义桌宠导入

当客户端 MVP 稳定后，开放 `.deskpet` 导入：

1. 用户选择 `.deskpet` 文件。
2. 客户端解包到临时目录。
3. 校验 manifest 和 Sprite Sheet。
4. 复制到 `%AppData%/DeskPet/pets/{localPetId}`。
5. 加入宠物列表。
6. 用户切换当前宠物。

### 12.2 网页端生成器接入

网页端生成器后续只需要产出符合本文档的 `.deskpet` 包。客户端无需知道素材是 AI 生成还是手绘。

### 12.3 动作扩展

可选扩展动作：

1. `sit`：坐下。
2. `stretch`：伸懒腰。
3. `groom`：舔毛。
4. `happy`：开心。
5. `angry`：生气。
6. `fall`：被拖拽松手后的落地。

新增动作只能作为可选字段，不得破坏 `formatVersion = 1` 的必须动作兼容性。
