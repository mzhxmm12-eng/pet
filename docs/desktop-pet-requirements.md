# Windows 桌面宠物需求文档

## 1. 产品定位

本产品是一款 Windows 端 2D 桌面宠物软件，核心卖点是让用户使用自己真实宠物的照片，生成独一无二的像素卡通桌宠，并让它在桌面上陪伴用户工作、走动、睡觉、被光标互动逗弄。

MVP 阶段不做复杂养成系统和大型工具箱，优先验证一个核心闭环：

用户上传宠物照片 -> 生成/编辑像素宠物形象 -> 桌宠出现在 Windows 桌面 -> 用户可以观看、拖拽、逗猫、切换动作 -> 保存为自己的专属桌宠。

推荐将产品拆成两个相对独立的模块：

1. 网页端形象生成器：负责上传照片、生成像素宠物、预览动作、导出宠物资产包。
2. Windows 桌宠客户端：负责导入宠物资产包，并在桌面上展示、移动、睡觉和互动。

这种拆分能让 AI 生成链路和桌面常驻链路解耦。网页端可以快速迭代生成效果，客户端则保持轻量、稳定、低资源占用。

## 2. 目标用户

### 主要用户

- 有猫、狗或其他宠物的 Windows 用户。
- 希望在工作或学习时获得陪伴感的用户。
- 对“自己的宠物变成桌宠”有明确情感需求的用户。

### 次要用户

- 喜欢像素风、桌面装饰、虚拟宠物的用户。
- 内容创作者、直播用户，需要可爱的桌面互动元素。

### 暂不优先服务

- 需要复杂生产力统计和企业管理能力的用户。
- 需要 3D 宠物、多人社交、宠物商城的用户。

## 3. 核心需求

### 3.1 用户真实需求

用户不是单纯想要“一个桌宠”，而是想要“自己的宠物”以可爱、像素、可互动的形式陪在桌面上。

因此产品第一优先级不是内置很多通用宠物，而是降低“把自家宠物变成桌宠”的成本，并让生成结果足够像、足够可爱、足够可拥有。

### 3.2 核心问题

用户通常没有像素画能力，也不懂动画切帧。产品需要把照片到可用桌宠素材的流程产品化，包括生成、预览、微调、保存和桌面运行。

## 4. 推荐技术架构

### 4.1 架构拆分

推荐采用“网页生成器 + Windows 桌宠客户端 + 生成服务”的三段式架构。

```text
用户浏览器
  -> 上传宠物照片
  -> 生成/编辑像素形象
  -> 导出 .deskpet 宠物资产包

Windows 桌宠客户端
  -> 导入 .deskpet 宠物资产包
  -> 解析素材与配置
  -> 在桌面运行宠物

生成服务
  -> 宠物抠图
  -> 像素风格化
  -> 动作帧生成
  -> 资产包打包
```

### 4.2 拆分理由

1. 降低 Windows 客户端复杂度：客户端不需要集成大型 AI 模型、GPU 依赖或复杂图片处理。
2. 提升生成体验：网页更适合做上传、对比、微调、候选图选择、失败重试。
3. 方便跨平台传播：用户即使没安装客户端，也可以先在网页上生成和分享宠物形象。
4. 便于商业化：网页端可以承载登录、额度、付费生成、历史作品管理。
5. 便于技术演进：生成模型、提示词、ComfyUI 工作流可以在服务端持续升级，不影响客户端稳定性。

## 5. 推荐技术栈

### 5.1 网页端形象生成器

推荐方案：`Next.js + React + TypeScript`

主要能力：

- 宠物照片上传。
- 生成状态展示。
- 多个候选结果对比。
- 像素风格选择。
- 基础特征微调。
- 动作预览。
- 导出 `.deskpet` 宠物资产包。

推荐组件：

- UI：`React + Tailwind CSS` 或成熟组件库。
- 图片上传：浏览器本地预览、裁剪、压缩。
- 动作预览：Canvas 或普通 Sprite Sheet 播放。
- 登录：MVP 可先不做；如果需要保存历史作品，再接入账号系统。

### 5.2 Windows 桌面客户端

推荐方案：`.NET 8/9 + WPF + Win32 API`

选择原因：

- WPF 适合做 Windows 原生桌面应用、托盘、设置页、透明无边框窗口。
- Win32 API 可处理顶层窗口、点击穿透、拖拽、全局鼠标位置、多显示器边界等桌宠关键能力。
- .NET 生态适合长期维护，安装包、自动更新、文件读写、系统托盘、SQLite 等都比较成熟。
- 相比 Electron，WPF 更轻量，适合常驻桌面的宠物程序。

备选方案：

- `Electron + React + TypeScript`：开发 UI 快，但常驻内存更高，不适合作为轻量桌宠首选。
- `Unity`：适合 3D 或复杂动画，不适合作为 2D 像素 MVP 的首选。
- `Qt / C++`：性能强、跨平台好，但开发成本更高；如果未来明确要跨平台，可重新评估。

### 5.3 桌宠渲染

MVP 推荐：

- WPF `Transparent Window` 承载宠物渲染层。
- 宠物素材使用 PNG 序列帧或 Sprite Sheet。
- 动画播放由客户端状态机控制。

后续可升级：

- 使用 `SkiaSharp` 做更高性能的 2D 渲染。
- 使用 Spine/DragonBones 类骨骼动画方案，但 MVP 不建议引入，素材生成链路会变复杂。

### 5.4 宠物生成服务

推荐架构：

- 客户端负责上传照片、展示生成结果、微调和保存。
- 后端负责图像生成、风格化、抠图、像素化、动作帧生成。

推荐技术：

- 后端：`Python + FastAPI`
- 图像处理：`Pillow + OpenCV`
- AI 生成：先接入外部图像生成 API 或自托管 Stable Diffusion/ComfyUI 工作流
- 存储：本地 MVP 可仅保存到用户本机；如果需要账号同步，再引入对象存储

MVP 建议不要一开始自研完整生成模型。更合理的方式是先搭建可替换的生成管线：

照片上传 -> 宠物主体识别/抠图 -> 像素风格化 -> 生成基础站立形象 -> 派生动作帧 -> 用户预览与挑选。

### 5.5 宠物资产包格式

建议定义统一资产包格式：`.deskpet`

本质可以是一个 zip 文件，内部包含配置文件和图片素材。

```text
mimi.deskpet
  manifest.json
  preview.png
  sprites/
    idle.png
    walk_left.png
    walk_right.png
    sleep.png
    alert.png
    play.png
  original/
    source-thumbnail.png
```

`manifest.json` 示例：

```json
{
  "formatVersion": 1,
  "petId": "pet_20260504_001",
  "name": "Mimi",
  "species": "cat",
  "style": "pixel_cute",
  "canvas": {
    "width": 64,
    "height": 64,
    "scale": 2
  },
  "animations": {
    "idle": {
      "file": "sprites/idle.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 4,
      "fps": 4
    },
    "walk_left": {
      "file": "sprites/walk_left.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 6,
      "fps": 8
    }
  }
}
```

客户端只需要实现 `.deskpet` 导入、校验、解析和运行，不关心素材是 AI 生成、人工绘制还是第三方制作。

### 5.6 本地数据存储

推荐：

- `SQLite`：保存宠物配置、动作状态、用户设置、已生成素材索引。
- 本地文件夹：保存 PNG/Sprite Sheet、缩略图、导入原图。

本地目录建议：

```text
%AppData%/DeskPet/
  pets/
    {petId}/
      original/
      sprites/
      config.json
  app.db
  settings.json
```

### 5.7 安装与更新

推荐：

- 安装包：`MSIX` 或 `Squirrel.Windows`
- 自动更新：MVP 可先做手动检查更新，后续再做静默更新
- 崩溃日志：本地日志优先，上传需用户同意

## 6. 功能需求

## 6.1 网页端：宠物形象生成

### Must Have

1. 用户可以上传 1-5 张自家宠物照片。
2. 系统生成至少 1 个像素卡通形象。
3. 用户可以预览生成结果。
4. 用户可以预览基础动作效果。
5. 用户可以导出 `.deskpet` 宠物资产包。

### Should Have

1. 支持选择像素风格：可爱、复古、Q版。
2. 支持选择宠物类型：猫、狗、其他。
3. 支持简单微调：主色、耳朵/尾巴特征、眼睛颜色、体型。
4. 支持重新生成。

### Could Have

1. 多角度生成。
2. 配饰系统，如蝴蝶结、围巾、帽子。
3. 用户手动像素编辑器。
4. 分享宠物形象包。

## 6.2 Windows 客户端：资产包导入

### Must Have

1. 用户可以导入 `.deskpet` 文件。
2. 客户端校验资产包结构和版本。
3. 客户端展示宠物名称、预览图、动作列表。
4. 用户可以将导入的宠物设为当前桌宠。
5. 导入后的资产保存到本地用户目录。

### Should Have

1. 支持拖拽 `.deskpet` 文件到客户端导入。
2. 支持双击 `.deskpet` 文件唤起客户端导入。
3. 支持删除已导入宠物。
4. 支持导入失败原因提示。

## 6.3 Windows 客户端：桌宠基础行为

### Must Have

1. 桌宠可以常驻桌面显示。
2. 桌宠支持透明背景。
3. 桌宠支持拖拽移动。
4. 桌宠支持在桌面范围内随机走动。
5. 桌宠支持 idle、walk、sleep 三种基础状态。
6. 用户可以右键打开菜单：隐藏、暂停、设置、退出。

### Should Have

1. 桌宠可以停靠在屏幕边缘。
2. 桌宠可以记住上次位置。
3. 支持多显示器。
4. 支持开机自启动。
5. 支持工作时间安静模式。

### Could Have

1. 桌宠坐在窗口边缘。
2. 桌宠根据时间自动睡觉。
3. 桌宠根据用户长时间无操作进入等待状态。

## 6.4 Windows 客户端：光标逗猫互动

### Must Have

1. 桌宠能感知光标靠近。
2. 光标靠近时，桌宠会抬头、警觉或看向光标。
3. 用户点击桌宠时，桌宠有反馈动作。
4. 用户拖动光标快速经过时，桌宠有追逐或扑一下的动作。

### Should Have

1. 光标悬停时，桌宠跟随光标方向转头。
2. 支持逗猫棒模式：用户按快捷键或菜单进入互动模式。
3. 逗猫过程中，桌宠会追逐光标一小段距离。

### Could Have

1. 桌宠根据互动次数产生亲密度。
2. 互动后触发撒娇、打滚、踩奶等特殊动作。

## 6.5 宠物资产与动作系统

### MVP 动作集

每个宠物至少需要以下动作素材：

1. `idle`：待机，2-4 帧。
2. `walk_left`：向左走，4-8 帧。
3. `walk_right`：向右走，4-8 帧。
4. `sleep`：睡觉，2-4 帧。
5. `alert`：注意光标，1-3 帧。
6. `play`：扑/玩耍，3-6 帧。

### 资产格式

推荐统一为：

```json
{
  "petId": "cat_001",
  "name": "Mimi",
  "scale": 2,
  "animations": {
    "idle": {
      "file": "idle.png",
      "frameWidth": 64,
      "frameHeight": 64,
      "frames": 4,
      "fps": 4
    }
  }
}
```

## 6.6 设置功能

### Must Have

1. 显示/隐藏桌宠。
2. 调整宠物大小。
3. 调整动画速度。
4. 开启/关闭点击穿透。
5. 开启/关闭开机启动。
6. 切换当前宠物。

### Should Have

1. 安静模式。
2. 多显示器显示位置。
3. 重置宠物位置。
4. 删除本地宠物素材。

## 7. 非功能需求

### 性能

1. 常驻内存尽量控制在 150MB 以内。
2. 空闲 CPU 占用尽量低于 2%。
3. 动画播放不能明显卡顿。
4. 全屏游戏或视频播放时可自动暂停或降低刷新。

### 兼容性

1. 支持 Windows 10 和 Windows 11。
2. 支持高 DPI 缩放。
3. 支持多显示器。
4. 支持锁屏、休眠恢复后的状态恢复。

### 隐私

1. 宠物照片默认只用于生成宠物形象。
2. 上传云端生成前必须明确告知用户。
3. 原图、生成图、宠物素材均可删除。
4. MVP 不采集键盘内容、不截屏、不读取聊天或窗口内容。

## 8. 建议 MVP 范围

### MVP 必做

1. 网页端上传宠物照片。
2. 网页端生成一个像素卡通宠物形象。
3. 网页端生成基础动作：待机、走路、睡觉、互动。
4. 网页端导出 `.deskpet` 宠物资产包。
5. Windows 客户端导入 `.deskpet` 文件。
6. Windows 客户端透明桌宠窗口。
7. 桌宠在桌面随机走动。
8. 光标靠近和点击互动。
9. 基础设置页。
10. 本地保存宠物形象和配置。

### MVP 暂不做

1. 复杂养成系统。
2. 商城和社区。
3. 多宠物同时运行。
4. 键盘敲击统计。
5. 摸鱼工具箱。
6. 宠物聊天 AI。
7. 3D 桌宠。

这些功能不是不重要，而是会稀释当前最强需求：用户想先拥有“自己的宠物桌宠”。

## 9. 推荐开发阶段

### 阶段一：桌宠运行内核

目标：先让一个固定像素猫能在 Windows 桌面上稳定运行。

功能：

- 透明无边框窗口。
- PNG 序列帧播放。
- idle/walk/sleep 状态机。
- 拖拽移动。
- 托盘菜单。

### 阶段二：资产包协议与导入

目标：让客户端支持导入标准 `.deskpet` 文件。

功能：

- `.deskpet` 结构定义。
- 资产包校验。
- 资产包导入。
- 切换当前宠物。

### 阶段三：网页生成器

目标：让用户上传自己宠物照片并得到可导入资产包。

功能：

- 图片上传。
- 调用生成服务。
- 生成形象预览。
- 动作预览。
- 导出 `.deskpet` 文件。

### 阶段四：互动体验

目标：让桌宠“活起来”。

功能：

- 光标靠近感知。
- 点击反馈。
- 追逐光标。
- 睡觉/醒来。
- 简单情绪状态。

### 阶段五：体验打磨

目标：提升留存与日常陪伴感。

功能：

- 安静模式。
- 开机启动。
- 多显示器。
- 尺寸/速度调整。
- 宠物命名。
- 简单配饰。

## 10. 技术风险

### 9.1 AI 生成结果不像用户宠物

风险：用户最关心“像不像我家的猫”。如果生成结果只是普通像素猫，会削弱核心价值。

应对：

- 上传多张照片。
- 让用户选择关键特征，如毛色、花纹、眼睛颜色。
- 生成多个候选。
- 提供轻量微调，而不是只给一次性结果。

### 9.2 动作帧生成不稳定

风险：静态形象容易生成，统一风格的多动作帧更难。

应对：

- MVP 先生成标准站立形象，再用模板动作进行适配。
- 对动作帧做强约束：统一尺寸、统一朝向、统一调色板。
- 必要时采用“用户宠物头部/花纹 + 通用身体动作模板”的混合方案。

### 9.3 桌面窗口交互复杂

风险：透明窗口、点击穿透、多显示器、DPI、全屏应用都可能带来兼容问题。

应对：

- 第一阶段先支持普通桌面场景。
- 提供“一键找回桌宠”和“重置位置”。
- 全屏应用场景默认暂停或隐藏。

### 10.4 资产包协议不稳定

风险：如果 `.deskpet` 格式频繁变化，客户端与网页端容易不兼容。

应对：

- 从第一版开始定义 `formatVersion`。
- 客户端导入时做版本检查。
- 保持向后兼容，新增字段不能破坏旧资产包。
- 将必须字段和可选字段分开。

## 11. 成功指标

### MVP 验证指标

1. 用户上传宠物照片后的生成完成率。
2. 用户是否选择生成结果作为桌宠。
3. 用户是否在生成后保留桌宠运行超过 10 分钟。
4. 用户第二天是否再次打开桌宠。
5. 用户对“像不像自己宠物”的主观评分。

### 核心判断

如果用户愿意说“这就是我家的猫”，产品方向就成立。后续再加入统计、摸鱼工具、养成系统才有意义。
